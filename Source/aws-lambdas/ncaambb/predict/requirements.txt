# The shared library (Source/library) is installed separately by the build
# workflow.

# Same package set and reasoning as
# Source/aws-lambdas/nba/predict/requirements.txt -- this Lambda's
# model_loader.py is a byte-for-byte copy of NBA's/NCAAFB's/NFL's own,
# dispatching on library.ml.model_types.ADAPTERS the same way, so it needs
# the same deserialization footprint regardless of which algorithm
# actually won any given NCAA MBB model's own backtest tournament.
#
# numpy/scipy: xgboost's own real runtime deps (installs --no-deps and
# won't pull them in on its own).
# scikit-learn/joblib/pandas: needed whenever a promoted model is a
# non-XGBoost candidate (LogisticRegression/RandomForest/MLP -- see
# library/ml/model_types.py's ADAPTERS).
# lightgbm: NCAA MBB's own CANDIDATES lists include LightGBM (same as
# NBA's, unlike NFL's/NCAAFB's, which don't use it yet) -- unconditional
# here for the same reason scikit-learn is, since which algorithm
# actually won any given target's tournament can change from one retrain
# to the next. Needs libgomp at runtime too -- see this directory's own
# Dockerfile.
#
# requests: season_projection.py imports library.http.ncaambb_core (for
# ap_poll_to_rank_by_team, a pure JSON-parsing helper -- this Lambda never
# actually makes an HTTP call itself), which imports library.http.client,
# which imports requests unconditionally at module load time. Without
# this, every invocation failed cold: "Unable to import module 'handler':
# No module named 'requests'" -- confirmed live 2026-09-13, broken since
# the ap_poll_to_rank_by_team import landed 2026-09-10 (136e331). Same
# pin every ingest/live-scores/schedule-sync Lambda's own requirements.txt
# already uses.
