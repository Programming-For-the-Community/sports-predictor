Why only predict is VPC-attached

Only the model-scoring Lambda is VPC-attached (private subnets, no public IP) as a defense-in-depth boundary, reaching DynamoDB/S3 only through Gateway Endpoints — no NAT Gateway needed (saves ~$32/mo per AZ this single-user project doesn't need). predict-read and live-scores deliberately skip the VPC hop entirely: neither ever calls anything but DynamoDB/S3 over the plain AWS API path, so the extra network hop would only add cold-start latency with no security benefit.

Fargate training retired — EC2 is the sole training path

A real canary run validated EC2 Spot/on-demand as both cheaper (~20% on verified active-training-time cost) and reliable, after three real bugs were found and fixed live. Feature engineering is untouched — still Fargate on-demand in public subnets. The reaper Lambda is an independent backstop against orphaned instances: the state machine's own scale-to-0 states only run on a clean completion, so the reaper's 10-minute poll is what catches a manually-stopped execution.
