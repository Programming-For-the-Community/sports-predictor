# Data Sources

Free-first, per sport. Where a genuinely free source has a quality or completeness gap, an optional paid upgrade is noted — but every sport has a free path that's enough to build and run the pipeline.

| Sport | Primary source (free) | Auth | Update cadence | Notes |
|---|---|---|---|---|
| NFL | nflverse / nflfastR | None | Weekly in-season (re-published files) | GitHub-hosted parquet/CSV files: play-by-play, schedules, rosters back to 1999. The most mature open sports data ecosystem of the six. |
| NCAA FB | CollegeFootballData.com (CFBD), FBS only | Free API key, 1,000 calls/month (registration required) | Near-daily | REST API v2 (`api.collegefootballdata.com`) covering games/teams/conferences, team & player stats, betting lines, recruiting, coaches, advanced metrics (EPA/PPA/win prob), and AP/Coaches/Playoff Committee rankings on the free tier. Weather, live scoreboard, and opponent-adjusted metrics are Tier 1+ (paid) only -- live scores instead come from the free ESPN scoreboard supplement below, at zero CFBD quota cost. Bulk per-week endpoints (`/games?year=Y&week=W`) keep the free tier workable across a whole season's ingest. |
| NBA | ESPN's public (unofficial) endpoints | None | Daily | nba_api (stats.nba.com) was tried first but is blocked by bot protection from typical cloud/datacenter IPs — a real deployment risk, not just a dev inconvenience, so it was dropped. balldontlie.io was also checked: its free tier only covers teams/players/games, not box scores/stats, and the tier that does is a paid subscription. ESPN matches NCAA MBB's own source below, which also makes live-scores id-matching trivial for both sports (same source for data and live-scores). |
| NCAA MBB | ESPN's public (unofficial) endpoints | None | Daily | Covers schedules, box scores, and play-by-play. Also the source for AP Top 25 poll data (`site.web.api.espn.com`'s own `/rankings` endpoint) — used to train the national-ranking model that seeds March Madness/conference-tournament field selection, same role CFBD's rankings play for NCAA FB. KenPom's advanced efficiency ratings are a paid optional add-on if you want them as a feature later. |
| PGA Tour | ESPN's public (unofficial) golf endpoints; Sports-Reference for historical backfill | None | Weekly (tournament-based, ~45 events/year) | Data Golf is a worthwhile optional paid upgrade — it publishes its own win/top-5/top-10/top-20/make-cut probability model alongside player skill ratings, which you could use directly as a baseline or as a feature input rather than building golf-specific modeling from scratch. |
| F1 | Jolpica-F1 (Ergast-compatible) | None, rate-limited to 200 requests/hour unauthenticated | Weekly (race-based, ~24 events/year) | Drop-in successor to the now-shut-down Ergast API, using the same endpoint structure. FastF1 (Python) wraps Jolpica and adds access to lap timing and telemetry summaries if you want richer features later — recommend storing only derived summaries (sector deltas, pit stop timing) rather than raw telemetry, which is large and unnecessary for outcome prediction. |

## Ingestion notes

**Polling frequency should match the sport's actual cadence**, not a single global schedule. In practice, both orchestrators run all 6 sports on the same fixed cadence (daily ingest, monthly training) and rely on each sport's `season_start`/`season_end` window for season gating rather than a per-sport polling interval -- the sport registry's own `polling_cadence` field (`DATA_SCHEMA.md`) is informational only today, not yet consumed by either state machine. Revisit if a sport's real cadence needs diverge enough (e.g. NBA/NCAA MBB's much higher games-per-day) to justify the added complexity.

**Treat unofficial/hidden APIs (ESPN, stats.nba.com) as best-effort.** They're free and reliable in practice, but undocumented endpoints can change without notice. Build the corresponding adapter's `fetch()` step to fail loudly (log and alert) rather than silently returning empty data, so a broken endpoint shows up as a CloudWatch alarm instead of a quietly stale model.

**Historical backfill is rate-limit-bound, not compute-bound.** Pulling 10 years of data respecting each source's request limits (Jolpica's 200/hour, in particular) will take real wall-clock time — plan for the backfill to run over a day or two in the background rather than expecting it to complete in one sitting.

**API keys are stored in AWS Secrets Manager, never as a GitHub secret or plaintext env var.** CFBD is the first source this project uses that requires one (every other source above is keyless). Two separate free CFBD accounts are registered -- one for production ingest, one for backfill -- so a month-long backfill run never competes with production ingest for the same 1,000-call budget. Both keys live as separate JSON fields (e.g. `ncaa_fb_ingest_key`, `ncaa_fb_backfill_key`) inside **one shared** Secrets Manager secret covering every sport's third-party API keys, created once out-of-band (console or `aws secretsmanager create-secret`, not Terraform); Terraform takes that single secret's ARN as one input variable (`var.third_party_api_key_secret_arn`, sourced from the `THIRD_PARTY_API_KEYS_SECRET_ARN` GitHub Actions secret), grants each calling Lambda/ECS task role a `secretsmanager:GetSecretValue` statement scoped to that one ARN, and passes the ARN itself into the environment as `CFBD_API_KEY_SECRET_ARN` -- the key value never appears in Terraform state, CI logs, or a GitHub secret. `library/http/cfbd.py` resolves the real field from Secrets Manager once at cold start and caches it for the container's lifetime. This is the standard pattern for any future sport's paid API key -- add a new field to the same shared secret, not a new Terraform-managed secret per sport.

**Deliberately excluded for now:** SportsRadar, Genius Sports, SportsDataIO, and similar commercial feeds. These offer broader coverage and guaranteed uptime SLAs, but at a monthly cost that doesn't make sense for a personal project when the free sources above already cover everything the model needs. Worth revisiting only if a specific free source becomes unreliable enough to be a real problem.
